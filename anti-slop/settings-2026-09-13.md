## Recorded interaction verification

Executed by `dotnet run --project verification/Smoke.csproj` using real WPF controls and routed events. Startup/update/logout effects use substituted service callbacks so tests do not change Windows startup or sign out the user's account.

- Opening: does not mutate preferences or invoke persistence callbacks.
- Floating/Left/Right/Top/Bottom: each updates dock preference; docked state locks topmost on; Floating restores editability.
- Always on top: updates the floating preference.
- Compact/Card/Detailed: each updates the stored layout choice.
- Black/White: updates theme preference and live resources; both rendered and inspected.
- Opacity: 20%, 42%, 100% update preference and visible number; 70% shown in preview.
- Windows login: success updates preference/callback; failure restores checkbox and shows retry message.
- Update: success displays result; failure enables retry; pending request displays loading and disables duplicate action; completion restores button.
- Sign out: failure preserves retry; success disables button and replaces account text.
- Small viewport: ScrollToEnd reaches Account; fixed footer remains within bounds.
- Done: closes settings without exiting the app; Escape is wired through native IsCancel.
- Exit app: closes settings and invokes app exit callback.
- Signed-out state: Sign out disabled.

Existing dock, refresh, reset-time, taskbar, feedback and icon checks also pass. Authentication against a live account and interactive Windows Installer upgrade remain manual checks; no credentials used by verification.
